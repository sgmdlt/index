# Битые данные из outbox не ретраятся, а уходят на перекачку

Если дело невозможно проиндексировать из-за самих данных — манифеста нет на диске (`path_missing`), в каталоге нет HTML (`docs_missing`), манифест не разбирается (`bad_manifest_json`), документ не собрался (`build_failed`), вместо карточки сохранена страница ошибки БД суда (`sql_error`) или пустая заглушка (`empty_html`) — строка outbox сразу получает терминальный статус `REDOWNLOAD`, а в `redownload_queue` пишется заявка на повторное скачивание (`queue_redownload`, идемпотентно по `(manifest_path, filename, reason)`). Повтор чтения тех же байтов результата не изменит; раньше такие строки пять раз проходили `FAILED` впустую.

## Consequences

- Ретраи (`mark_failed`, до `MAX_ATTEMPTS = 5`) остаются только для неожиданных ошибок — например, временного сбоя ES.
- Ошибка разбора одного HTML дела перекачку не вызывает: у дела бывает несколько файлов, один плохой не делает дело негодным.
- Сам перекачивающий воркер — вне index.
