# Граница courts / index: courts сохраняет оригинал, index строит Индексный ID

courts отвечает за сохранение: скачивает карточки и передаёт индексатору оригинал, то есть HTML карточки и поля строки выдачи в том виде, в каком их показал суд. Индексный ID — сущность индекса, и строит его только индексатор, только из оригинала. Всё, что courts вычислил сам (`ID`, `hashed_id`, свой ключ загрузки, поля, подменённые из своей БД), индексатор не принимает на веру: либо пересчитывает из оригинала, либо не использует. Решили так после courts-1ctj и аудита courts-2ymt. Индексный ID обязан быть детерминированной функцией сохранений (ADR 0001), а ID, который выставляет courts, зависит от состояния его БД: `watch_identity` берёт дату из найденной записи и собирает номер так, чтобы формула вернула прежний ключ.

## Consequences

- Формула Индексного ID живёт в index и меняется только здесь. Копия `build_case_id` в courts становится формулой ключа загрузки и может разойтись с формулой индекса. Общий эталон двух репозиториев больше не обязателен.
- courts не переписывает поля оригинала из своего состояния. Поля строки выдачи считаются оригиналом наравне с карточкой: часть номера «~ М-…», по которой строятся Индексные ID гражданских дел, есть только в строке выдачи.
- Ключ, по которому courts сверяет и отслеживает дела (`downloaded_cases`, Redis), называется ключом загрузки. Для индекса он ничего не значит.
- Переход: пока индексатор где-то читает `ID`/`id_final` из манифеста или courts подменяет поля оригинала, это нарушение. Устраняется в courts-2ymt.
