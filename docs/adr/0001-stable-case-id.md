# id дела — детерминированная функция данных: формула + правило группы по uuid

`_id` дела в ES — `{суд}_{дата регистрации}_{номер}`, где номер — **первый выданный номер карточки** по формуле `build_case_id`. Формула живёт в index (`src/utils/case_id.py`, эталон `tests/fixtures/case_id_golden.json`); до ADR 0005 источником истины считался courts, а здесь лежала побайтовая копия. Для карточек с `uuid` (case_uid карточки sudrf) id — функция **всех** скачиваний: побеждает формульный id с самой ранней датой, при равной — от самой свежей записи, затем лексикографически меньший (`src/uuid_group.py`). Индекс должен пересобираться с нуля, поэтому «первый увиденный id» ключом быть не может: id не должен зависеть от порядка индексации. Номер на sudrf со временем меняется, а суд правит дату задним числом — отсюда дубли одного дела под разными `_id` (courts-271g).

## Considered Options

- **`uuid` как `_id`** — его нет у ~76 млн из 218 млн документов (МГС, старые карточки с пустым `_uid=`), и адреса всех существующих дел пришлось бы сменить.
- **Дата события «Регистрация…» из движения дела** — у ~60% документов её нет, а где есть, она на 99,5% уже совпадает с датой в id.

## Consequences

- Правило детерминизма (courts-2ymt): входы id — только оригинал сохранений (номер, дата регистрации, суд, UID карточки, как их показал суд). Не входят текущее время, порядок и разбиение сохранений на пачки и прогоны, поля, которые индексатор вычислил или перезаписал (`fix_date_reg`, слияние), состояние ES сверх id близнецов. Проверяет `tests/test_determinism.py` на настоящем ES с `refresh_interval=-1`; исключение — только записью здесь с причиной.
- id пересчитывается из полей записи для любого источника (манифест, JSONL, ES); сохранённый `id_final` — только если пересчёт невозможен.
- `BulkIndexer` перед записью ищет в ES документы того же `uuid` под другим `_id`, вливает их в целевой и удаляет. Перед поиском — refresh индекса: при `refresh_interval=-1` иначе поиск не видит пачек этого же прогона, и близнецы из разных пачек расходятся (courts-2ymt.2; держать в памяти uuid → id прогона дешевле, но при полной пересборке это ~57 ГБ). Пачки пишутся по одной, чтобы близнецы не разминулись в соседних потоках. Сбой refresh или поиска (как и `mget`) валит пачку, а не пишет вслепую.
- Близнец, уже лежащий в ES, участвует в правиле группы формульным id из своего номера и **даты из своего ID дела**, а не из `date_reg`: та могла пройти `fix_date_reg` (эвристика, зависящая от «сегодня») или быть исправлена судом позже. Поэтому правка даты задним числом не сдвигает ID дела — самая ранняя дата держится между сохранениями, а не только внутри одной пачки (courts-1ctj).
- Сливаем только при совпадении формульного id или `uuid`; по похожести номеров — никогда. Близнец на формульном id с другим `uuid` — на ручной разбор.
- МГС (`mos-gorsud.ru`) ключуется своим правилом и в формулу и правило группы не входит.
- Индексный ID — сущность индекса: формулой и правилом группы владеет index, ID из манифеста courts не принимается на веру (ADR 0005).
