# id дела — детерминированная функция данных: формула + правило группы по uuid

`_id` дела в ES — `{суд}_{дата регистрации}_{номер}`, где номер — **первый выданный номер карточки** по формуле `build_case_id`. Формула живёт в courts (источник истины) и побайтово скопирована в `src/utils/case_id.py`; обе копии прогоняются по одному эталону `tests/fixtures/case_id_golden.json`. Для карточек с `uuid` (case_uid карточки sudrf) id — функция **всех** скачиваний: побеждает формульный id с самой ранней датой, при равной — от самой свежей записи, затем лексикографически меньший (`src/uuid_group.py`). Индекс должен пересобираться с нуля, поэтому «первый увиденный id» ключом быть не может: id не должен зависеть от порядка индексации. Номер на sudrf со временем меняется, а суд правит дату задним числом — отсюда дубли одного дела под разными `_id` (courts-271g).

## Considered Options

- **`uuid` как `_id`** — его нет у ~76 млн из 218 млн документов (МГС, старые карточки с пустым `_uid=`), и адреса всех существующих дел пришлось бы сменить.
- **Дата события «Регистрация…» из движения дела** — у ~60% документов её нет, а где есть, она на 99,5% уже совпадает с датой в id.

## Consequences

- id пересчитывается из полей записи для любого источника (манифест, JSONL, ES); сохранённый `id_final` — только если пересчёт невозможен.
- `BulkIndexer` перед записью ищет в ES документы того же `uuid` под другим `_id`, вливает их в целевой и удаляет. Сбой этого поиска (как и `mget`) валит пачку, а не пишет вслепую.
- Сливаем только при совпадении формульного id или `uuid`; по похожести номеров — никогда. Близнец на формульном id с другим `uuid` — на ручной разбор.
- МГС (`mos-gorsud.ru`) ключуется своим правилом и в формулу и правило группы не входит.
- courts применяет только формулу; правилом группы владеет index.
