# Слияние фрагментов дела — в Python перед `_bulk`, в ES уходит целый документ

Когда один `_id` приходит несколькими фрагментами (несколько HTML одного дела, повторные скачивания, близнецы по `uuid`), `BulkIndexer` читает текущий документ (`mget`), сливает поля `MERGE_FIELDS` в Python (`merge_docs`) и пишет результат операцией `index`, а не `update` со скриптом ES. Так повторный прогон на тех же данных идемпотентен — фрагменты схлопываются, — а правила слияния (акт с тем же текстом — один акт, даже если пробелы расходятся; самый ранний `created_at` у слитых близнецов) тестируются как чистые функции.

## Consequences

- Запись дела всегда полная: если `mget` не ответил, пачка валится целиком, иначе документ перезаписался бы без уже лежащих в ES фрагментов.
- Правила слияния задаются в `elastic_index_dict.json` (`"type": "merge"`) и в `bulk_indexer.py`, а не в painless-скриптах.
